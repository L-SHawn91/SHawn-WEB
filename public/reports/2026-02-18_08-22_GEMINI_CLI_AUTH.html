핵심 요약

Executive Summary

  • 원인: Gemini CLI의 Login with Google 인증 경로가 정책 플래그로 비활성화.
  • 영향: 로그인 기반 CLI는 실패하지만, API Key 기반 호출은 정상 가능.
  • 운영 결론: 당분간 Kimi + OpenCode를 주력, Gemini는 API Key 경로 중심으로 제한 운영.
  • Cause: Gemini CLI Login with Google auth path is policy-disabled.
  • Impact: Login-based CLI fails, while API-key calls can still succeed.
  • Ops decision: Keep Kimi + OpenCode as primary; use Gemini mostly via API key path.

운영 액션 플랜

Operational Action Plan

  • 기본 병렬 조합: Kimi CLI + OpenCode
  • Gemini는 API Key 경로 우선 사용, 로그인 경로는 보조/점검용
  • 오류정책: 401/403 즉시 격리, 429는 30~60분 쿨다운, timeout 1회 재시도
  • 정기 점검 리포트에 경로별 상태(로그인/API/CLI)를 분리 표시
  • Primary parallel combo: Kimi CLI + OpenCode
  • Use Gemini mainly via API key; keep login path as secondary/check-only
  • Error policy: isolate on 401/403, cooldown 30–60m on 429, one retry on timeout
  • Report path-level health separately (login/API/CLI) in regular ops reports
