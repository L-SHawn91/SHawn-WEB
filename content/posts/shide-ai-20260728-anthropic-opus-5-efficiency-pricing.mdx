 새  AI  모델이   나올   때마다   비슷한   숫자가   쏟아집니다.   벤치마크   점수,   입력   가격,   출력   가격,   토큰   절감률이   한꺼번에   등장합니다.   숫자는   많은데,   막상   “그래서   내가   쓰면   무엇이   좋아지고   얼마가   드는가?”라는   질문에는   답하기   어렵습니다.

 Anthropic이   2026년   7월   24일   공개한  Claude Opus  5도   마찬가지입니다.   Anthropic은  Opus  5가   자사의   고성능   장기   작업   모델인  Fable  5에   가까운   성능을   내면서  API  가격은   절반이라고   설명합니다.   여기에   작업마다   AI가   생각하는   양을   조절하는  `effort`  설정도   넣었습니다.

 이   문장만   보면   “성능은   거의   같은데   가격만   반으로   내린   모델”처럼   들립니다.   하지만   실제   비용은   그렇게   단순하지   않습니다.   답변이   길어지거나   같은   일을   여러   번   다시   시키면   청구액이   늘어납니다.   반대로   한   번에   정확히   끝내고   사람이   고치는   시간까지   줄인다면,   표시   가격보다   더   큰   절감이   생길   수   있습니다.

 이   글에서는  Opus  5를   처음   접하는   사람도   이해할   수   있도록   이름과   가격부터   차근차근   풀어보겠습니다.   결론부터   말하면,  Opus  5의   장점은   무조건   가장   똑똑하다는   데   있지   않습니다.  ** 중요한   일에는   계산을   더   쓰고,   쉬운   일에는   계산을   줄여서   한   모델을   더   경제적으로   사용할   수   있다는   점 ** 이   핵심입니다.

> 먼저 한 줄로 정리하면 Claude Opus 5는 Anthropic이 만든 고성능 AI 모델입니다. 최고 성능만 좇기보다, 실제 업무에서 필요한 만큼만 계산하도록 조절해 비용을 관리하는 데 초점을 맞췄습니다.

## 1. Anthropic, Opus 5, Fable 5는 각각 무엇인가

 먼저   이름부터   정리하겠습니다.

**Anthropic** 은   Claude를   만드는   미국  AI  기업입니다.   OpenAI가  GPT  시리즈를   만들고   Google이   Google AI를   만드는   것처럼,   Anthropic은   Claude라는  AI  모델군을   개발합니다.

**Claude Opus 5** 는   Anthropic이   일상적인   고난도   업무에   쓰도록   내놓은   모델입니다.   긴   문서를   읽거나,   여러   파일에   걸친   코드   오류를   찾거나,   도구를   여러   번   사용해야   하는   작업을   염두에   두고   있습니다.

**Fable 5** 는   Anthropic이   더   어렵고   오래   걸리는   범용   작업에   배치한   고성능   모델입니다.   며칠   동안   이어지는   자율   작업이나   실패했을   때   손실이   큰   문제를   겨냥합니다.   대신  Opus  5보다  API  가격이   높습니다.   공격적   사이버보안이나   장시간   생물학   연구처럼   특수한   영역에는  Mythos  5라는   별도   상위   모델이   있습니다.

 여기서  “API  가격”은   일반   구독료와   다릅니다.   개발자가   자신의   서비스나   자동화   프로그램에서   Claude를   호출할   때   사용량만큼   내는   비용입니다.   예를   들어   고객   문의   1만   건을   자동   분류하거나,   사내   문서   수백   개를   요약하는   시스템을   만들면  API  사용량에   따라   요금이   붙습니다.

`토큰` 도   알아둘   필요가   있습니다.   토큰은   AI가   글을   읽고   쓸   때   사용하는   작은   텍스트   조각입니다.   단어   하나가   토큰   하나와   정확히   같지는   않습니다.   그래도   처음에는   “AI가   읽고   쓴   글의   양을   세는   단위”라고   이해하면   충분합니다.

## 2. 무엇이 얼마나 저렴해졌나

Opus  5의   표준  API  가격은   입력   100만   토큰당  ** 5달러 **,  출력   100만   토큰당  ** 25달러 ** 입니다.

- 입력 토큰: 사용자가 AI에게 보내는 질문, 문서, 코드

- 출력 토큰: AI가 작성해서 돌려주는 답변

 출력이   입력보다   다섯   배   비쌉니다.   그래서   긴   보고서를   계속   생성하는   작업은   질문을   보내는   비용보다   답변을   받는   비용이   더   커질   수   있습니다.

Opus  5의   가격은   이전   모델인  Opus  4.8과   같습니다.   Anthropic의   최상위   모델인  Fable  5와   비교하면   절반입니다.   같은   양의   글을   넣고   같은   양의   답변을   받는다는   단순한   조건에서는  Opus  5가  Fable  5보다  50%  저렴합니다.

 Anthropic은  Opus  5를  Claude  Max의   기본   모델로   배치했습니다.  Claude Pro  이용자가   선택할   수   있는   모델   중에서도   가장   강한   축에   넣었습니다.   특별한   날에만   꺼내   쓰는   고가   모델보다,   매일   사용하는   강한   모델에   가깝게   설계한   것입니다.

 빠른   답변이   필요한   사용자를   위한  **Fast mode** 도   있습니다.  Anthropic  발표   기준으로   표준   모드보다   약   2.5배   빠릅니다.   대신   가격도   두   배입니다.  Fast  mode는   성능을   공짜로   올려주는   설정이   아닙니다.   사람이   화면   앞에서   결과를   기다리거나,   몇   분의   지연이   서비스   운영에   직접   영향을   줄   때   추가   요금을   내고   시간을   줄이는   선택입니다.

 밤새   실행하는   자료   정리나   예약   작업이라면   굳이  Fast  mode를   쓸   이유가   적습니다.   반대로   개발자가   오류   수정   결과를   기다리며   작업을   멈춘   상태라면,   두   배   가격을   내더라도   빠른   응답이   더   경제적일   수   있습니다.   결국   속도의   가치는   사용   상황에   따라   달라집니다.

## 3. effort 설정은 ‘AI가 얼마나 오래 생각할지’ 정하는 스위치다

`effort` 는   낯선   표현이지만   개념은   어렵지   않습니다.  ** AI가   한   문제에   얼마나   많은   계산과   답변   분량을   사용할지   정하는   설정 ** 입니다.

 낮은   effort를   고르면   AI가   비교적   짧게   생각하고   빠르게   답합니다.   비용은   줄어들지만   복잡한   예외를   놓칠   수   있습니다.   높은   effort를   고르면   더   많은   계산을   쓰고   중간   과정을   더   점검합니다.   어려운   문제에서   성공할   가능성은   높아질   수   있지만   시간과   비용도   늘어납니다.

 예를   들어   업무용   이메일   100개의   주제를   분류한다고   해보겠습니다.   결과가   조금   틀려도   사람이   금방   발견할   수   있습니다.   이런   일에   매번   최고   effort를   쓸   필요는   없습니다.

 반면   결제   오류가   난   서비스의   코드를   고치는   일은   다릅니다.   AI가   여러   파일을   읽고,   오류가   생긴   조건을   찾고,   수정한   뒤   테스트까지   실행해야   합니다.   이때는   높은   effort가   유리할   수   있습니다.   첫   답변이   조금   비싸더라도   잘못된   수정과   재시도를   줄이면   전체   비용은   오히려   내려갑니다.

 중요한   계약서나   재무   자료를   검토하는   일은   더   조심해야   합니다.   높은   effort만   켜고   끝낼   문제가   아닙니다.   별도의   검토   모델과   사람의   최종   확인도   필요합니다.   AI가   더   오래   생각했다고   해서   법적·재무적   책임까지   대신   지는   것은   아니기   때문입니다.

### 낮은 effort

** 쉬운   예시 **
 이메일   분류,   형식   변경,   짧은   요약

** 어떻게   쓰면   좋은가 **
 빠르게   처리하고   일부   결과를   표본   검사

** 주의할   점 **
 복잡한   예외를   놓칠   수   있음

### 중간 effort

** 쉬운   예시 **
 긴   문서   정리,   일반적인   코드   수정

** 어떻게   쓰면   좋은가 **
 품질과   비용을   함께   비교

** 주의할   점 **
 테스트와   출처   확인   필요

### 높은 effort

** 쉬운   예시 **
 복잡한   디버깅,   여러   도구를   쓰는   분석

** 어떻게   쓰면   좋은가 **
 실패   비용이   큰   작업에   제한적으로   사용

** 주의할   점 **
 모든   요청에   쓰면   절감   효과가   사라짐

### Fast mode

** 쉬운   예시 **
 사람이   결과를   기다리는   긴급   작업

** 어떻게   쓰면   좋은가 **
 시간이   돈보다   중요한   경우에   사용

** 주의할   점 **
 표준   모드의   두   배   가격

### Fable 5

** 쉬운   예시 **
 며칠   동안   이어지는   최고   난도   작업

** 어떻게   쓰면   좋은가 **
Opus  5로   부족한   작업만   올려보냄

** 주의할   점 **
 쉬운   작업에는   지나치게   비쌈

 이처럼   effort는   단순한   성능   버튼이   아닙니다.  ** 업무의   중요도에   따라  AI  사용료를   다르게   배정하는   기능 ** 에   가깝습니다.

## 4. 벤치마크 점수는 어떻게 읽어야 하나

 벤치마크는  AI  모델에   같은   시험   문제를   풀게   해서   성능을   비교하는   표준   평가입니다.   학교   시험과   비슷하지만,   코딩·컴퓨터   조작·도구   사용처럼   평가하려는   능력마다   시험지가   다릅니다.

 Anthropic은   여러   벤치마크에서  Opus  5가   비용   대비   높은   성능을   보였다고   발표했습니다.

- Frontier-Bench v0.1에서는 Opus 4.8보다 더 낮은 작업당 비용으로 두 배가 넘는 성능을 보였다고 설명했습니다.

- CursorBench 3.2의 최대 effort에서는 Fable 5 최고점과의 차이가 0.5% 이내였고, 작업당 비용은 절반이었다고 발표했습니다.

- OSWorld 2.0에서는 Fable 5의 최고 결과를 약 3분의 1을 조금 넘는 비용으로 넘어섰다고 밝혔습니다.

- AutomationBench에서는 같은 비용을 썼을 때 다음 순위 모델보다 통과율이 약 1.5배 높았다고 보고했습니다.

 여기서  `작업당 비용` 은   모델을   한   번   부르는   가격과   다릅니다.   한   과제를   실제로   끝낼   때까지   사용한   토큰,   재시도,   도구   호출을   모두   고려한   비용입니다.

 간단한   예를   들어보겠습니다.   저렴한   모델이   한   번   시도할   때   0.20달러지만   평균   세   번   시도해야   일을   끝낸다면   총   0.60달러가   듭니다.   더   강한   모델이   한   번에   0.40달러를   쓰고   성공한다면   호출당   가격은   더   비싸도   완료된   작업   한   건의   비용은   0.20달러   낮습니다.   여기에   사람이   잘못된   결과를   고치는   시간까지   더하면   차이는   더   커질   수   있습니다.

 그래서  Opus 5  발표에서   봐야   할   것은   “몇   점으로   1등했는가”만이   아닙니다.  ** 같은   예산으로   실제   일을   몇   건   끝낼   수   있는가 ** 가   더   중요한   질문입니다.

 다만   Anthropic이   공개한   숫자를   그대로   모든   업무에   적용하면   안   됩니다.

 첫째,   주요   수치는   Anthropic이   직접   실행한   평가와   Anthropic이   선정한   초기   고객   사례에서   나왔습니다.   Frontier-Bench의   일부   결과는   Anthropic이   지정한   평가   실행   프로그램,   모델   연결   환경,   과제당   5회   시도의   평균입니다.   이   평가   실행   프로그램을   기술   문서에서는  `하네스` 라고   부릅니다.

 둘째,   코딩   시험을   잘   봤다고   해서   계약   검토나   과학   연구도   같은   폭으로   좋아진다고   단정할   수   없습니다.   Anthropic은   내부   생명과학   평가에서  Opus  4.8보다   유기화학   성능이   10.2%포인트,   단백질   변이   관련   작업은   7.7%포인트   향상됐다고   발표했습니다.   그러나   이   수치도   독립   연구기관이   검증한   결과와는   구분해야   합니다.

 셋째,   평균   점수는   큰   실수가   얼마나   자주   발생하는지   충분히   보여주지   못합니다.   실제   서비스에서는   평소   답변이   조금   좋은   것보다,   위험한   변경   앞에서   멈추고   사람에게   확인을   요청하는   능력이   더   중요할   수   있습니다.

 따라서   도입하려는   조직은   공개   순위만   보지   말고   다음을   함께   측정해야   합니다.

- 첫 시도에 일을 제대로 끝낸 비율

- 같은 일을 다시 시킨 횟수

- 사용한 입력·출력 토큰과 외부 도구 호출 횟수

- 사람이 결과를 수정하는 데 걸린 시간

- 잘못된 결과를 되돌리는 데 든 비용

## 5. 실제 월 사용료를 계산해보면

 가격이   어떻게   청구되는지   구체적인   숫자로   계산해보겠습니다.

 한   달에  AI  요청   1만   건을   처리한다고   가정하겠습니다.   요청   한   건마다   평균   2만   입력   토큰을   보내고,   AI가   평균   4천   출력   토큰으로   답한다고   해보겠습니다.

 한   달   총사용량은   다음과   같습니다.

- 입력: 2만 토큰 × 1만 건 = 2억 토큰

- 출력: 4천 토큰 × 1만 건 = 4천만 토큰

Opus 5  표준   가격을   적용하면   다음과   같습니다.

- 입력 비용: 2억 토큰 ÷ 100만 × 5달러 = 1,000달러

- 출력 비용: 4천만 토큰 ÷ 100만 × 25달러 = 1,000달러

- 합계: 월 2,000달러

 같은   사용량을  Fable  5나  Opus 5 Fast  mode로   처리하면   단가가   두   배이므로   월   4,000달러가   됩니다.

 Anthropic이   소개한   초기   고객   사례처럼   비슷한   품질을   유지하면서   출력   토큰이  26%  줄었다고   가정해보겠습니다.   출력   비용은   1,000달러에서   740달러로   내려갑니다.   입력   비용   1,000달러는   그대로이므로   총액은   1,740달러입니다.

 출력   토큰은  26%  줄었지만   전체   청구액은   2,000달러에서   1,740달러로  ** 13%만   감소 ** 합니다.   “토큰을  26%  적게   썼다”는   말을   “전체   비용도  26%  줄었다”로   받아들이면   안   되는   이유입니다.

 반대로  Opus  5가   일을   한   번에   끝내   재시도와   사람의   수정   시간을   줄인다면   실제   절감률은   13%보다   커질   수   있습니다.   Anthropic이   공개한   한   금융   모델링   사례에서는  Opus  4.8보다   정확도가   평균   9%포인트   높았고,   대화   차례와   도구   호출이   3분의  1  줄었으며,   완료   시간은  60%  짧았다고   보고했습니다.

 여기서  `대화 차례` 는   사용자가   요청하고   AI가   답하는   한   번의   왕복을   뜻합니다.  `도구 호출` 은   AI가   검색,   코드   실행,   파일   읽기   같은   외부   기능을   사용한   횟수입니다.   두   수치가   줄면   토큰뿐   아니라   실행   시간과   외부   서비스   비용도   줄   수   있습니다.

 다만   이   금융   사례는  Anthropic  발표에   포함된   초기   고객   평가입니다.   모든   기업에서   같은   결과가   나온다는   보장은   없습니다.   구매를   확정하는   증거라기보다,   자체   시험에서   확인해볼   만한   가설로   보는   편이   정확합니다.

## 6. 어떤 업무에서 차이를 체감할 수 있나

### 여러 파일에 걸친 코드 오류 수정

 짧은   코드   한   줄을   작성하는   일보다,   오래된   서비스에서   오류의   원인을   찾는   일이   훨씬   어렵습니다.   AI는   관련   파일을   찾고,   실제   오류를   재현하고,   코드를   바꾸고,   테스트를   실행해야   합니다.

 Anthropic은  Opus  5가   겉으로   드러난   증상만   고치지   않고   버그의   근본   원인을   찾거나,   검증   자료가   없을   때   자체   테스트를   만들어   확인한   사례를   소개했습니다.   실제로   이런   능력이   재현된다면   토큰을   몇   퍼센트   줄이는   것보다   훨씬   큰   절감이   생깁니다.   잘못된   코드를   “수정   완료”라고   보고한   뒤   사람이   다시   원인을   찾는   시간이   줄기   때문입니다.

### 계약서와 재무 자료 검토

 법률   문서의   수정   제안을   뜻하는  `redline`,  재무   모델링,   기업   실사   자료   분석은   숫자와   근거가   맞아야   합니다.   Anthropic이   소개한   초기   사용자들은   낮은   effort에서도   품질이   유지되거나   첫   시도의   숫자   추론이   좋아졌다고   평가했습니다.

 하지만   계약서와   재무   자료는   틀렸을   때   손실이   큽니다.   따라서   실제   도입   전에는   기존   모델과  Opus  5에   같은   문서를   넣고   결과를   나란히   비교해야   합니다.   이런   비교를  `A/B 테스트` 라고   합니다.   누락   조항,   잘못된   숫자,   근거   없는   결론을   사람이   직접   확인해야   합니다.

### 과학 연구 보조

 Anthropic은   구조생물학,   유기화학,   생물정보학   평가에서도   이전   모델보다   향상됐다고   발표했습니다.   긴   논문을   읽고   실험   아이디어를   정리하거나,   분석   코드를   검토하는   보조   도구로는   유용할   수   있습니다.

 다만   AI가   자신   있게   말하는   것과   과학적으로   맞는   것은   별개입니다.   인용   논문의   실제   내용,   원자료   분석,   통계   결과를   다시   확인해야   합니다.  Opus  5가   실험   증거나   연구자의   판단을   대신하는   것은   아닙니다.

## 7. 모든 요청을 Opus 5에 보내면 오히려 낭비다

Opus  5의  effort  설정을   제대로   쓰려면   업무를   난도별로   나눠야   합니다.   기술   문서에서는   이런   분배   규칙을  `라우팅` 이라고   부릅니다.   쉽게   말해,  ** 들어온   일을   알맞은   모델과   설정으로   보내는   교통정리 ** 입니다.

 처음부터   복잡한   자동   시스템을   만들   필요는   없습니다.   다음처럼   시작할   수   있습니다.

- 이메일 분류, 형식 변경, 짧은 요약은 작은 모델이나 낮은 effort로 처리합니다.

- 긴 문서 분석, 일반적인 코드 수정은 Opus 5의 중간 effort로 시작합니다.

- 테스트가 실패하거나 여러 도구가 필요하면 높은 effort로 한 단계 올립니다.

- 두 번 실패했거나 되돌리기 어려운 변경이면 Fable 5 같은 상위 모델과 사람 검토로 넘깁니다.

- 모델 호출 가격이 아니라 완료된 작업 한 건의 총비용을 기록합니다.

 예를   들어   고객   문의   제목을   붙이는   일에   최고   설정을   쓰는   것은   낭비입니다.   반대로   결제   시스템   오류를   단순   모델에   여러   번   맡기다   실패하면   처음부터   강한   모델을   쓴   것보다   더   비싸질   수   있습니다.

 이렇게   업무별   경로를   나누면   “어떤   AI가   세계   최고인가”라는   추상적인   논쟁이   줄어듭니다.   대신   “우리   업무에서는   어떤   설정이   가장   적은   비용으로   안정적으로   끝났는가”를   측정할   수   있습니다.

## 8. 반값이어도 실제 비용이 늘어나는 경우

Opus  5의   표시   가격이  Fable  5의   절반이라는   사실은   명확합니다.   그렇다고   어떤   상황에서나   최종   비용이   절반이   되는   것은   아닙니다.

** 답변이   지나치게   길   때 **

 출력   단가는   입력보다   다섯   배   비쌉니다.   필요하지   않은   장문   보고서를   계속   만들면   출력   비용이   빠르게   늘어납니다.   답변   형식과   최대   길이를   미리   정하는   편이   좋습니다.

** 같은   설명을   매번   다시   보낼   때 **

 긴   지시문이나   반복   문서를   재사용하는   기능을  `프롬프트 캐시` 라고   합니다.   캐시는   이전에   보낸   내용을   다시   활용해   중복   처리를   줄입니다.   도구   구성을   자주   바꾸면서   캐시가   깨지면   같은   내용을   반복해   읽히는   비용이   생길   수   있습니다.

** 싼   모델이   계속   실패할   때 **

 호출당   단가는   낮아도   세   번,   네   번   다시   시키면   전체   비용이   커집니다.   실패한   결과를   사람이   고치는   시간까지   포함해야   합니다.

**Fast  mode가   필요하지   않은데   항상   켤   때 **

 야간   작업이나   사람이   기다리지   않는   예약   작업에서   두   배   가격의  Fast  mode를   고정으로   쓰면   비용만   늘어날   수   있습니다.

** 자동   폴백을   확인하지   않을   때 **

`폴백` 은   첫   번째   모델이   요청을   처리하지   못할   때   다른   모델로   자동   전환하는   기능입니다.   서비스   오류는   줄일   수   있지만,   실제로   어떤   모델이   응답했는지   확인하지   않으면   예상보다   비싼   모델   사용량이   늘어날   수   있습니다.

 결국   비용   관리는   모델   하나의   가격표만   보는   일이   아닙니다.   답변   길이,  effort,  재시도,   캐시,   도구   사용,   사람의   검토   시간을   함께   봐야   합니다.

## 9. Opus 5를 어디까지 믿어야 하나

Opus  5가   모든   영역에서   가장   강한   모델은   아닙니다.   Anthropic은   공격적   사이버보안과   며칠   동안   이어지는   자율   생물학   연구에서   더   전문적인   상위   모델인  Mythos  5보다   뒤처진다고   밝혔습니다.

 Anthropic은   사이버   공격에   직접   쓰일   수   있는   일부   훈련을   의도적으로   제한했다고   설명합니다.   취약점을   찾는   능력은   좋아졌지만,   실제   공격   코드를   만드는   작업에서는   차이가   있다는   뜻입니다.

“Fable  5에   가까운   성능”이라는   표현도   모든   과제에서   동일하다는   뜻은   아닙니다.   며칠   동안   이어지는   작업,   대규모   시스템   변경,   보안·법률·재무처럼   실패   비용이   큰   결정에는   여전히   상위   모델과   사람의   감독이   필요합니다.

 반대로   단순   요약이나   반복   분류라면  Opus  5도   과한   선택입니다.   작은   모델이   충분히   정확하다면   그   모델을   쓰는   편이   더   경제적입니다.

 가장   중요한   한계는   공개   근거의   상당   부분을   Anthropic이   직접   만들었다는   점입니다.   독립   벤치마크와   실제   청구   데이터가   더   쌓이기   전까지   “어떤   업무든   반값에   같은   성능”이라고   받아들이면   안   됩니다.   정확한   표현은   이렇습니다.

**Opus  5는   반값에   가까운   성능을   낼   가능성을   보여줬지만,   실제   절감률은   각   조직이   자신의   업무로   확인해야   합니다. **

## 10. 도입 전에 직접 확인할 것

Opus  5를   기존   모델과   한꺼번에   교체하지   말고,   실제로   자주   하는   업무   30~100건을   골라   짧게   비교하는   편이   안전합니다.

- 기존 모델과 Opus 5에 같은 입력 자료와 같은 도구를 제공합니다.

- 낮음·중간·높음 effort를 각각 시험합니다.

- 첫 시도 성공률, 재시도 횟수, 토큰, 도구 호출, 사람의 수정 시간을 기록합니다.

- 이메일 분류와 복잡한 코드 수정처럼 난도가 다른 작업을 한 점수로 섞지 않습니다.

- 개인정보, 보안, 법률, 연구 결과처럼 위험한 작업은 사람이 최종 확인합니다.

- 2주 뒤 호출당 가격이 아니라 완료된 작업 한 건의 총비용을 비교합니다.
